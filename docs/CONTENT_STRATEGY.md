# Content strategy

Lead with work that can be understood quickly and explored deeply. The homepage introduces Shourya, places Nova and Neurofly first, then offers a smaller creative gallery, concise engineering notes, an undated selected-practice preview, about and direct email contact. No Education section.

## Voice

Concise, technically literate, human and factual, following the explicit supplied brief. Use “developing”, “designed to”, “experimental” and “future direction” where needed. Explain the problem before naming implementation tools. No inflated impact claims, invented dates or generic motivational biography. The supplied GitHub profile's terse builder description is consistent with this voice; no suitable long-form personal writing reference was found in returned public-profile results, so no unrelated private sources were searched.

## Evidence and depth

`SOURCE_MAP.md` distinguishes primary-attested project direction from inspected implementation evidence. Do not imply a GitHub file proves runtime reliability. Nova has an exact verified public repository; Neurofly does not. The Neurofly page is intentionally explicit about its evidence limit. Credentials, leadership titles and award ranking stay omitted until independent source links are supplied.

Project pages progress from plain-language summary through question, approach, conceptual architecture and expandable engineering details to current limits and next direction. A reader can understand the intended system without opening the technical sections. The conceptual previews are not demos or screenshots.

## Creative selection

Drive was accessible. Four final design images were selected after visual inspection: LinkScope, Identix, Clarion AI, Spectra AI. These are presented as visual-design compositions. Their product names are artwork titles, not additional software projects or verified client relationships. Keep the section smaller than Nova/Neurofly. No unreviewed editing footage is embedded. OmniCore is retained locally but excluded as visually redundant.

## Explorations

Two short notes frame actual project design questions: validation versus verification and olfactory sensing to navigation. Neither invents experimental findings. Local Markdown frontmatter uses `title`, `description`, `topic`; no artificial publication dates. Add future notes as files only after checking each factual claim.

## Resume

Use the shared content objects. Order: identity/contact, concise summary, selected projects, independent creative work, verified leadership if supplied, verified achievements if supplied, grouped capabilities, verified certifications if supplied. Hide empty sections instead of displaying unavailable claims. Print uses selectable text, normal links and a linear reading order. Do not stretch an evidence-limited resume with speculative filler.

## Maintenance

New factual entries require a matching source-map record before publication. Keep missing information internal; public UI must never render TODOs. Media paths: `public/media/nova-demo.mp4`, `public/media/neurofly-demo.mp4`, `public/media/shourya-profile.jpg`. Creative entries use local files under `public/media/creative/` plus their original Drive source links.
